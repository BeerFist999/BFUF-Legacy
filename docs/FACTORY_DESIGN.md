# Factory Design

## Назначение Factory

Factory — будущий модуль создания интерфейсных объектов в архитектуре BFUF. Его задача — централизованно собирать базовый Unit Frame из контейнера, элементов и выбранного Layout, не принимая на себя ответственность за игровое состояние или хранение данных.

## Основные обязанности

- Создание базовых Unit Frame.
- Создание контейнеров.
- Регистрация фреймов.
- Создание элементов.
- Подключение элементов.
- Применение Layout.

## Что Factory НЕ должен делать

- Не работать с игровой логикой.
- Не хранить настройки.
- Не знать о Database.
- Не обновлять Health.
- Не обновлять Power.
- Не работать с Aura.

## Публичный API

Ниже перечислены будущие методы Factory. На текущем этапе они описывают контракт модуля и не имеют реализации.

- `CreateUnitFrame(unit)` — создаёт базовый Unit Frame для указанного игрового юнита.
- `CreateContainer(frame)` — создаёт контейнер, принадлежащий переданному фрейму.
- `CreateElement(type)` — создаёт элемент указанного типа.
- `AttachElement(frame, element)` — подключает созданный элемент к фрейму.
- `ApplyLayout(frame)` — применяет Layout к фрейму и его элементам.
- `RegisterFrame(frame)` — регистрирует готовый фрейм в системе BFUF.

## Жизненный цикл создания Unit Frame

```text
Init
↓
Bootstrap
↓
Factory
↓
CreateUnitFrame
↓
CreateContainer
↓
Attach Elements
↓
Apply Layout
↓
Register Frame
```

## Принципы

- Factory отвечает только за создание объектов.
- Все игровые элементы реализуются отдельными модулями.
- Factory не содержит игровой логики.
- Максимальная модульность.
- Минимум зависимостей.
