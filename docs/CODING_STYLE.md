# Стиль разработки

## API и зависимости

- Используйте только API Blizzard, доступный в целевых клиентах World of Warcraft.
- Не используйте Ace3 и его компоненты.
- Не добавляйте сторонние библиотеки без отдельного архитектурного решения.

## Архитектура

- Следуйте модульной архитектуре.
- Один файл соответствует одному модулю и одной ясно определённой зоне ответственности.
- Взаимодействие между модулями должно быть явным; избегайте неявных глобальных зависимостей.
- Инициализацию, обработку событий и представление отделяйте друг от друга, когда это оправдано.

## Комментарии и документация

- Комментарии в исходном коде пишутся на русском языке.
- Комментируйте причины нетривиальных решений, а не очевидные действия кода.
- Обновляйте документацию при изменении публичного поведения или архитектуры.

## Именование

- Используйте единый стиль именования во всём проекте.
- Имена модулей, файлов и публичных сущностей должны быть понятными и предметными.
- Для Lua-переменных и функций используйте `camelCase`; для констант — `UPPER_SNAKE_CASE`.
- Не используйте неясные сокращения, кроме общепринятых терминов Blizzard API.
- Имя файла должно отражать имя и назначение модуля.

## Качество кода

- Предпочитайте простой и читаемый код избыточным абстракциям.
- Не дублируйте логику: выносите повторяющиеся операции в модульные функции.
- Проверяйте поведение в поддерживаемых версиях игры.

## BFUF.toc

- При изменении `BFUF.toc` никогда автоматически не меняйте значение `## Interface`. Изменяйте его только по явному запросу разработчика или при выходе новой версии World of Warcraft.
